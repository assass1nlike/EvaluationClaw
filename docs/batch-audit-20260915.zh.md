# 15 路实验的框架错误核查

核查目录：`benchmark-output/batch-25-20260914-rerun2`。范围为已结束的 11、12、14、15、16、17、19、20、22、23、24、25 路；其中 15 在检查期间结束。13、18、21 路未干预。

这 12 路初始规划共 240 道题，其中 112 道为 agent 题；初始评测保留的 agent 题为 0。已有报告分数不能用于判断 agent 题的难度或目标模型的工具操作能力。

| 问题 | 证据 | 修复与验证边界 |
| --- | --- | --- |
| Docker 环境被兼容性检查误拒绝 | 多路 Builder 最终响应的环境为 `docker_workspace`，诊断却要求改成同一类型。Python 模式序列化返回枚举成员，直接 `str()` 得到的不是枚举值。 | 当前兼容性检查按枚举值比较；补充 Python/JSON 两种序列化的回归用例，保留对 VM 的拒绝。 |
| 工具结果未与调用完整配对 | 14 路 analyser-03 最后一批请求 2 个工具，只返回 1 个结果；20 路 analyser-01 请求 3 个，只返回 2 个，随后均发生 HTTP 400。 | 超出预算的调用也返回对应 ID 的预算错误，实际读取次数不超额。模拟批量调用验证下一轮协议完整。 |
| 迭代继承初始 20 题配置 | 11、17 等路日志显示先构建 20 题再截到 2～3 题；审查时又按原维度目标补回 20 题，部分迭代扩到 21 或 25 题。 | 迭代使用独立配置，题量上限传入 Planner 并在构建前审计；审查修改同样受总量约束，不再事后截断。迭代难度由其目标决定。 |
| 局部补题收到矛盾数量 | 15、19 路补题目标分别为 3、8，Planner 输入仍要求 20，最终耗尽修复次数。 | 局部规划输入总数与维度目标一致，并明确父 benchmark 的数量只提供上下文。 |
| 预算耗尽仍要求新 goal | 12 路 analyser-04 已给出最终分析、空 goal、`done=false`，剩余迭代为 0，解析器仍报缺少 goal。 | 预算耗尽时保留分析并结束，不再要求不可执行的新任务；两种 analyser 模式均覆盖。 |
| 缺失正文被错误归为适配器错误 | 16 路 analyser-03 的响应含 12,836 个 reasoning tokens，正文为空、finish_reason=stop。 | 标记为缺失最终内容，允许一次有界恢复；不把思考内容当答案。持续失败明确记录。 |
| 分析异常阻断主评测导出 | 25 路探针审查返回自然语言拒答而非 JSON，解析失败后整次运行未导出报告。 | 允许一次保持原判断的格式修复；持续失败返回带错误状态的分析报告，保留主评测、已完成迭代和审查前的探针快照。失败报告不冒充分析结论，也不阻止后续恢复。 |
| 文件名被编辑路径拆开 | 15 路 `dimension_3_task_design_1` 的 tool-round-099 用 `tasks.0.environment.visible_files.BRIEF.md` 写入文件，形成 `BRIEF: {md: ...}`，最终类型检查失败。 | Builder 读写工具支持字面键路径数组，例如 `["tasks",0,"environment","visible_files","BRIEF.md"]`。点路径仍可用于普通字段。 |
| 强制提示词逐一列出 agent 文件名 | 11、25 路的归档资产因提示词未逐字引用文件名被拒绝。 | agent 可以通过探索发现文件；保留资产存在性和路径检查，非 agent 图片引用规则不变。 |
| Planner 未获知运行端的环境限制 | 15 路规划了 VM GUI 故障题，但本次使用 OpenClaw shell harness。 | Planner 可见环境按已选 harness 筛选，并在计划审计时验证环境和 actor 兼容性。 |
| HTTP 诊断缺少服务端错误正文 | 两次 HTTP 400 的上层记录仅包含通用状态错误，无法读出服务端具体解释。 | 在流关闭前读取错误正文，与状态码一起脱敏保存；回归检查持久化内容。 |

离线复核使用各 Builder job 最早一次构建调用的最后一份 `attempt-*.diagnostics.json` 所指向的响应，按当前解析、资产路径归一化与严格结构检查重新校验，启用参考轨迹和构题自检要求，并指定 OpenClaw。112 道候选中 87 道通过；其余仍含空题干、缺失环境或评分命令、资产不存在、非法字段、损坏的文件映射或不兼容环境。这些历史题目未自动改写。

本次没有重新调用模型、构建 Docker 镜像或重新评分。结构检查通过不等于任务环境、题目质量或评分器已通过端到端验证。原实验结果和仍在运行的进程均保留。

验证：`.venv/bin/pytest -q` 全量 694 项通过；本次修改涉及的 Python 文件通过 Ruff 检查，`git diff --check` 通过。
