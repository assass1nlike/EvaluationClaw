# Analyzer 获取的信息

Analyzer 在主评测完成后，根据基准题目、模型结果和验证轮次历史提出能力假设，并据此请求新的验证题。它收到的信息分为默认上下文和按需读取的完整证据。

默认上下文中的题目信息包括每道题的题目内容、所属维度、题型、难度、选项和评分 rubric。agent 题目还会附带环境契约摘要：环境类型（如 `docker_workspace` 或 `vm`）、镜像、网络与资源限制、setup 和执行命令、评测配置，以及可见、隐藏和运行时文件的路径列表。文件内容不会放入默认上下文。

默认上下文中的模型结果按 target 和 item 记录，包含得分、错误信息、judge reasoning，以及 `failure_evidence`。其中 `failure_evidence.failed` 表示该结果是否低于满分或发生错误，`reason` 汇总错误或 judge 对失败原因的说明。模型原始回答默认保留一个有界的开头和结尾片段，使最终回答、收尾动作和末尾错误仍然可见；过长响应中间部分会标记为截断。

上下文还包括主评测的汇总分数、基准目标和维度定义，以及每一轮验证中 Analyzer 的分析、任务设计、实际生成的题目和运行结果。这样后续轮次可以看到先前假设是否得到验证。

默认上下文不会提供选择题正确选项、精确答案文本、隐藏文件内容或凭证，避免 Analyzer 根据答案泄漏构造题目。环境契约用于解释题目实际要求，gold 信息仍由评测器掌握。

当摘要不足以判断失败原因时，Analyzer 可以调用两个只读工具：

- `read_item_evidence` 根据 `target_id` 和 `item_id` 读取某道题的完整模型响应（包括完整 agent trajectory）和 judge reasoning；
- `read_run_artifact` 读取当前运行目录中的指定文本 artifact，例如 `run.json`、评测输出和已收集的 trajectory 文件。

这两个工具受当前运行目录限制，并有返回字符数上限。Analyzer 应先使用默认的题目契约、得分和失败原因；只有需要区分模型能力问题与 setup、环境或评测器问题时，才读取完整证据。
